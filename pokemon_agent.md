System Specification: Autonomous Hybrid RL-LLM Handoff Architecture for Pokémon Crystal (GBC)
This specification defines a modular, spec-driven blueprint designed for autonomous implementation via CLI coding agents (e.g., Claude Code, Cursor, or phase-gated developer harnesses). Every component has strict type interfaces, deterministic state invariants, and self-verifying unit/simulation tests so an agentic coding tool can build, test, and debug one phase at a time without polluting its context window.
1. Repository Structure & Agentic Coding Workflow
To prevent an agentic coding tool from hallucinating cross-module imports or breaking emulator timing invariants, the repository is partitioned into isolated, contract-bound subsystems with a compiled .sym lookup table serving as the single source of truth for memory addresses.

2. Unconsidered Engineering Factors (Critical for Pokémon Crystal)
Before writing code, six non-obvious hardware and systems traps in Pokémon Crystal (GBC / MBC3) must be engineered into the core substrate:
2.1 Zero-Hardcoded Hex via pokecrystal.sym Parsing
Unlike Pokémon Red, where community projects copy-paste raw hex addresses (0xD35E), Pokémon Crystal uses 8 switchable 4KB Work RAM banks (WRAM0 at 0xC000–0xCFFF and switchable WRAM1–WRAM7 mapped into 0xD000–0xDFFF, controlled by hardware register SVBK at 0xFF70). Furthermore, addresses shift between Crystal v1.0 and v1.1.
Solution: Clone pret/pokecrystal and compile the ROM using RGBDS (make), which outputs pokecrystal.sym. Every symbol is formatted as BB:AAAA SymbolName (e.g., 01:D4E2 wPlayerStandingMapX).
PyBoy Banked Direct Access: Instead of reading pyboy.memory[0xD4E2] (which reads whichever WRAM bank happens to be active on that CPU cycle and corrupts your state vector during screen transitions), always read pyboy.memory[bank, addr] using the exact (bank, addr) tuple parsed from pokecrystal.sym.

2.2 Deterministic MBC3 Real-Time Clock (RTC) & PRNG Seeding
Pokémon Crystal uses an MBC3 hardware Real-Time Clock. If 64 parallel RL workers run at 150 real-time speed while reading the host OS system clock, wild encounter tables (data/wild/johto_grass.asm) will flip unpredictably between Morning, Day, and Night mid-rollout, breaking reproducibility.
Solution: Implement RTCController in src/core/rtc_controller.py that overrides hHours and wTimeOfDay in RAM at the start of every episode (or locks RTC registers via PyBoy memory hooks) so time of day is a controllable environment parameter passed by Tier 1 (target_time_of_day: Literal["MORN", "DAY", "NITE"]). Similarly, lock the hardware divider and PRNG bytes (hRandomAdd, hRandomSub) during deterministic unit tests.
2.3 Concurrency-Safe Shared Navigation Graph (SQLite WAL + Shared Memory)
When 5 Ghost Scouts (Tier 2) and 1 Main Agent (Tier 3) simultaneously discover tiles and off-screen NPC positions, writing to a flat nav_memory.json file causes race conditions and corrupted JSON reads.
Solution: Store the persistent world graph in an in-memory/disk SQLite database in WAL (Write-Ahead Logging) mode (nav_memory.db) with tables maps(group_id, map_id, width, height), tiles(group_id, map_id, x, y, walkability, tile_id, last_seen_step), npcs(group_id, map_id, obj_idx, x, y, movement_type, is_trainer), and warps(src_group, src_map, src_x, src_y, dst_group, dst_map, dst_x, dst_y). Expose a read-only connection (?mode=ro) to Tier 1 (planner_agent.py) so the LLM can never alter map state.
2.4 Asynchronous Non-Blocking LLM Planning & Watchdog Recovery
If Tier 1 (LLM Director) takes 4–8 seconds to reason over a sub-goal, blocking the vectorized training or scout pool wastes thousands of emulator frames.
Solution: When a sub-goal finishes or stalls, the main emulator freezes on a safe overworld frame while Ghost Scouts continue mapping adjacent edges asynchronously. Every LLM output is validated against a strict Pydantic schema with AST sandbox verification for Eureka reward snippets (banning import, open, exec, eval, __).
2.5 Move-Replacement & Evolution Interrupt Handler
When a Pokémon levels up in combat and learns a 5th move (e.g., Quilava learning Flame Wheel at Level 14 or Smokescreen), or attempts to evolve post-battle, the game enters a modal dialog inside or immediately after wBattleMode that breaks standard battle or overworld policies.
Solution: The Tier 2 Interrupt Router monitors wMoveSelectionMenuType and evolution state flags. For move replacement, Tier 2 computes the expected DPS/utility delta of the new move vs. the 4 current moves using the LSTKAG move table; if the new move strictly dominates the weakest move (e.g., replacing Tackle with Flame Wheel or deleting a non-HM normal move), a deterministic macro overwrites that slot. (Note: in Crystal, HMs cannot be overwritten without the Blackthorn Move Deleter, so Tier 1 strictly assigns HMs like Cut or Whirlpool to designated utility slots).

Worker B: Goal-Conditioned Recurrent PPO Explorer (worker_b_explorer.py)
Combines PokeRL's anti-loop spatial masking with Rekursiv AI's Craftax architecture:
Action Space: Discrete(5) — ['UP', 'DOWN', 'LEFT', 'RIGHT', 'A'] (START and SELECT are hardware-masked out; B is automatically pulsed during text-box dismiss macros).
Observation Space (Ot):
screen_stack: uint8[4, 72, 80] — 4 stacked downsampled grayscale frames.
visited_mask: float32[1, 72, 80] — Centered per-map binary mask where visited (x, y) tiles on the current (wMapGroup, wMapNumber) are 1.0 and unvisited tiles are 0.0.
local_tile_grid: int32[9, 10] — Exact on-screen collision/tile ID matrix read from wTilemap + cached off-screen NPC markers within a 910 viewport.
teduo_state_vec: float32[32] — Masked WRAM vector filtered by Tier 1's TEDUO mask F(x,g)sg.
Neural Architecture (8.5M Parameters):
Visual + Mask Encoder: 3-layer NatureCNN over concatenated [screen_stack, visited_mask] (5 x 72 x 80) 256-d.
Craftax Local Board Encoder: Embedding layer (256 tile IDs 16-d) + 2-layer 33 CNN over local_tile_grid (9 x 10) 128-d.
State & Goal Encoder: 2-layer MLP over teduo_state_vec 128-d.
Recurrent Core: GRUCell(input_size=512, hidden_size=512) (retains memory of off-screen NPCs and split-floor blockers across steps).
Three Output Heads:
Policy Head $\pi_\theta(a_t \mid h_t)$: Linear(512, 5)
Value Head V(ht): Linear(512, 1) (also queried by Tier 2 for SayCan affordance gating!)
Craftax Auxiliary Action-Effect Head $P_\psi(\Delta \text{screen} \mid h_t, a_t)$: Linear(512 + 5, 1) with binary cross-entropy loss predicting whether action at alters the center 7280 frame by more than 2% pixel L1 norm (teaches immediate wall, ledge, and NPC affordances).
Reward Scaling & Anti-Loop Shaping (Rekursiv Craftax + PokeRL):
No [-1,1] Reward Clipping: Raw step rewards are divided by a fixed constant REWARD_SCALE = 8.0 so sub-goal completion (+10.0 / 8.0 = +1.25) always dominates novel tile discovery (+0.05 / 8.0 = +0.00625).

Worker C: Combat Specialist & Fast Rollout Simulator (worker_c_combat.py)
State Translator (wram_to_gen2_state()): Reads wPartyMons and wEnemyMon from Bank 01 on every battle turn prompt (wBattleMenuCursorPosition ready) and constructs a canonical Gen 2 battle state tensor compatible with UT-Austin-RPL/metamon (Superkazam / Kakuna Gen2OU checkpoints).
Dual-Mode Execution:
Wild / Routine Trainer Mode: Single forward pass (<15ms) through the Metamon Transformer conditioned on a 1-hot mission scalar: FIGHT_OPTIMAL (trainer battle), GRIND_FAST_OHKO (select highest-PP 100%-acc move that KOs), CATCH_TARGET (status + Pokéball if wEnemyMonSpecies == target_id, else Run), or EVADE_LOW_HP (immediate Run).
Boss / Gym Leader Mode (wBattleMode == 2 & Boss ID): Runs a 3-ply PokéChamp Expectiminimax Search using a lightweight Cython/Rust Gen 2 damage & speed calculator (calc_gen2_damage(attacker, move, defender, weather, screens)) where leaf nodes are scored by the Metamon value head Vcombat(s).
3.2 Tier 2: Affordance Handoff Broker (src/tier2_broker/)
SayCan Affordance Gating (saycan_gate.py):
Before dispatching any Tier 1 candidate sub-goal $g_k \in \{g_1, \dots, g_K\}$ with LLM log-probability score $p_{\text{LLM}}(g_k \mid s)$, Tier 2 computes the physical affordance $p_{\text{affordance}}(g_k \mid s)$:
For Navigation/Puzzle Sub-goals: Queries a deterministic prerequisite checklist (e.g., has_badge(PLAINBADGE) and party_has_move(STRENGTH)) multiplied by the normalized value head (V(ht,gk)) of Worker B.
For Boss Sub-goals (CHALLENGE_GYM): Clones the current party state from WRAM and runs 100 vectorized headless combat rollouts in Python/Cython against the boss's canonical roster from data/knowledge_graph/trainers.json.
Veto Rule: If $p_{\text{affordance}}(g_k \mid s) < \tau_{\text{ready}}$ (default 0.65 for bosses, 0.20 for navigation), Tier 2 vetoes the sub-goal without moving a single step in the main emulator and returns a structured VetoDiagnosticReport JSON to Tier 1.
5x Parallel Ghost Scouts (ghost_scouts.py):
Whenever the agent enters a map where unexplored_border_tiles > 0 or A* returns NoPathFound, Tier 2 forks the current PyBoy state (pyboy.save_state(io_bytes)) across 5 background worker processes:
Scout 1: Wall-follower (Left-hand rule) with walk_wait=16
Scout 2: Wall-follower (Right-hand rule) with walk_wait=16
Scout 3: North-East biased random walk with orthogonal sidestep reflex (walk_wait=20)
Scout 4: South-West biased random walk with orthogonal sidestep reflex (walk_wait=20)
Scout 5: Worker B policy at high temperature (=1.8)
Every discovered walkable tile, one-way ledge jump, warp transition, and off-screen NPC coordinate (wMapObjects) is written immediately to nav_memory.db. The millisecond a scout touches the sub-goal target coordinate or warp, Tier 2 halts Worker B and switches the main emulator to Worker A (A* Autopilot) along the newly discovered path.
Craftax Hard Stall Cap (critique_verifier.py):
Tracks steps_since_last_milestone_or_subgoal. If steps_since_last_subgoal >= 2,500 (local sub-goal stall) or steps_since_last_milestone >= 10,000 (Craftax hard cap), Tier 2 halts execution, rolls back to the pre-subgoal checkpoint if trapped in a soft-lock (e.g., mis-pushed boulder in Ice Path), and escalates to Tier 1 with the full trajectory heatmap.

4. Mass Simulation & Training Optimization Architecture
To train Worker B (the 8.5M-parameter Recurrent PPO Explorer) and run mass campaign evaluations at 40,000+ emulator frames per second (FPS) on a single workstation or GPU node, implement the following four systems optimizations:
4.1 Zero-Copy SharedMemory Vectorized PyBoy Pool (vec_env_shm.py)
Standard gymnasium.vector.AsyncVectorEnv pickles numpy arrays across Python multiprocessing pipes on every step, spending >60% of CPU time on IPC serialization.
Pre-allocate a single contiguous POSIX shared memory block (multiprocessing.shared_memory.SharedMemory) at startup for N=64 or 128 headless PyBoy processes (window="null", sound=False, sound_emulated=False).
Each PyBoy worker writes its 7280 downsampled screen, 7280 visited mask, 910 local tile grid, and 32-d WRAM vector directly into its slice of the shared memory buffer.
On the GPU host process, wrap the shared memory buffer in torch.frombuffer(...).pin_memory() and transfer the entire batch of 128 environments to CUDA in a single asynchronous DMA transfer (non_blocking=True).
Frame-Skip & Action Decimation: Each RL step executes a full macro-tick (16–20 emulator frames for turn+step) inside Cython/PyBoy before returning to Python, yielding an effective 16 speedup over frame-level RL.
4.2 Rekursiv Craftax "Frontier Practice" Curriculum Buffer (frontier_buffer.py)
To prevent parallel RL workers from wasting 90% of their steps in New Bark Town or early routes:
Maintain a priority ring buffer of Frontier Checkpoints. Whenever any worker reaches a new (wMapGroup, wMapNumber) floor, solves a new wEventFlags bit, or achieves a new maximum campaign score for the first time, serialize a tuple:


FrontierEntry=PyBoy`.state`bytes,htR512GRUhiddenstate,SQLite`nav_memory`snapshot
The 20% Frontier Reset Rule: On every episode reset (done or 10,000-step stall cap), 80% of workers reset to the current curriculum stage start state, while 20% of workers sample a state directly from the FrontierBuffer—restoring both the PyBoy RAM state and the agent's recurrent hidden state ht. This concentrates high-density rollout practice directly on mid/late-game bottlenecks (Sprout Tower 3F, Union Cave B2F, Morty's invisible floor puzzle, Ice Path boulder rooms).
