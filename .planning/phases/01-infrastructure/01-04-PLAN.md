<objective>
Save, name, and check game snapshots. A snapshot is a PyBoy state file plus a manifest row. It is not a model checkpoint. Do not write `.pt` files, hidden states, or a frontier buffer.

Wave 2, parallel with 01-03 and 01-05. No shared files with those plans.
</objective>

<context>
From 01-01: `STATES_DIR`, `MANIFEST_PATH`, `ROM_SHA1`, `sha1_bytes`, `Emulator`.
From 01-02: `RamParser`, `GameState.not_ready_reasons`, `to_text`, `to_dict`.

`StateEntry`: name, file, description, map `(group, number)`, pos `(x, y)`, badges, party count, time of day, rom sha1, state sha1, created_at, tags.

`StateRegistry(root=STATES_DIR)`:

- `names`, `get`, `path`, `load_bytes` (rejects a file whose hash does not match the manifest).
- `capture(emu, parser, name, description="", tags=(), force=False, overwrite=False)`.
- `register_file` for a `.state` made earlier by `crystal_smoke.py`.
- `validate` reloads each file, compares map, pos, badges, party count, both hashes, and `rom_sha1 == ROM_SHA1`.

Manifest JSON: `{"version": 1, "states": {name: entry}}`, written by temp file then `os.replace`. Names match `^[a-z0-9_]+$`.
</context>

<task type="auto">
  <name>Task 2: Play and save several snapshots</name>
  <files>tools/make_state.py</files>
  <action>
`python -m tools.make_state [--from NAME | --from-path FILE] [--autosave-every 60]`. Opens a window at speed 1 with the clock unlocked so a person can play.

A background thread only reads stdin. All emulator calls stay on the main thread. Commands: `save NAME [description]`, `force NAME [description]`, `pos`, `list`, `speed N`, `quit`, `help`. Every 30 frames, one status line: map, position, facing, badges, and READY or the not-ready reasons. `save` uses the registry and refuses a not-ready game unless `force`. Every `--autosave-every` seconds, if ready, write `states/_autosave/auto_{k%5}.state` (five files, not registered). Closing the window prints the names saved this session.
  </action>
  <verify>

  </verify>

</task>

<task type="auto">
  <name>Task 3: Import a cartridge save</name>
  <files>tools/import_sav.py</files>
  <action>
`python -m tools.import_sav PATH.sav --name NAME [--desc] [--tags] [--max-seconds 120] [--window] [--keep-ram]`.

Crystal SRAM is 32768 bytes. Longer files are truncated to that with a warning. Shorter files are an error. Back up an existing `rom/pokemon_crystal.gbc.ram`, write the save there, boot, and press start and A until the map is not (0, 0) for 60 frames in a row. Then stop pressing A, tick 120, and press B a few times if a text box is still up. If the snapshot is ready, register it. Restore the previous `.ram` in a `finally` unless `--keep-ram`. Always `stop(save=False)`. If the time budget runs out, exit 1 and tell the user to finish in `make_state`.
  </action>
  <verify>
    <automated>.venv/bin/python -m tools.import_sav --help && .venv/bin/python -c "import tools.import_sav"</automated>
  </verify>
  <done>The command imports, and the RAM backup is restored even when the boot fails.</done>
</task>
