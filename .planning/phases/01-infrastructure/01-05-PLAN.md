<objective>
Run a saved game forward for a fixed number of steps and write down what happened. The "player" in this plan is only a test double: a fixed list of buttons, or a seeded random choice among the four directions and A. That double exists so the loop can be tested. It is not a policy network and it does not call a model.

No cost meter, no pricing file, no agent-versus-baseline report. Those belonged to the language-model pitch and are out of this phase.

Wave 2. Does not import `src.states` or `src.step`. The command-line tool may import the registry.
</objective>

<context>
From 01-01: `Machine`, `Emulator`, `RUNS_DIR`, `sha1_bytes`, `ROM_SHA1`.
From 01-02: `GameState.to_dict()`, `RamParser`.

`Action`: kind is `press`, `wait`, or `done`. `button`, `frames` (default 8), `settle` (default 16).

`Script` protocol: `reset(state, seed)` and `act(state) -> Action`. Provide `RandomScript` (directions plus A, seeded) and `ButtonScript` (a list, then `done`).

`EpisodeRunner.run(script, state_name, *, max_steps, timeout_s, seed) -> EpisodeResult`.

Loop: load bytes, `load_state`, read state, then until the budget, a timeout, or `done`: act, press or wait, read state, append a JSON line. The line has step, frame, action, and `state.to_dict()`. No token fields.

Header line: episode id, script name, state name, state sha1, rom sha1, seed, max steps, start time. Footer: outcome (`step_budget`, `timeout`, `script_done`, `error`), steps, frames.

`FileStateSource` loads `states/<name>.state` or a literal path. Outcome `error` still writes the footer.
</context>
