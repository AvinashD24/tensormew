<objective>
Record the buttons of a run and play them back from the same snapshot. This is so a bug or a demo can be repeated. It is not a training replay buffer.

Wave 3. Depends on the emulator, the memory reader, and the episode runner.
</objective>

<context>
From 01-01: `InputEvent`, `add_listener`, `load_state` resets `frame` to 0, `screen_image`, `rtc_lock`.
From 01-05: the runner's start and end hooks. Add an optional listener object the runner already calls if present: `on_start(info)`, `on_end(result)`. Do not otherwise change the runner loop.

`InputRecorder` subscribes on start and writes `runs/<id>.inputs.jsonl` on end:

- Header: episode id, state name, state sha1, rom sha1, `rtc_locked: true`, total frames, final `GameState.to_dict()`, screen sha1.
- One line per event: frame, button, `p` or `r`.

`replay(...)` loads the snapshot, applies events on their frame, ticks one frame at a time, and returns whether map, position, party count, badges, and screen sha1 match the header. Screen hash is `sha1_bytes` of `screen_image().tobytes()` after a final rendered tick.

`FrameDumper` keeps every Nth RGB frame and writes a GIF. MP4 only when `ffmpeg` is on `PATH`, via a subprocess argument list with no shell. If ffmpeg is missing, say so and do not pretend the MP4 was written.
</context>
