<objective>
Move the player one tile, and wait out a map change. That is the whole plan.

Crystal will not walk onto a new tile until the character is already facing that way, so one step is "turn if needed, then walk." When the map id changes, wait 180 frames so the warp animation finishes. This is the physics the PDF puts in the emulator wrapper.

This is not the autopilot. No pathfinding, no door sidestep, no grass or ledge costs, no NPC avoidance, no scout processes.

Depends on the emulator and the memory reader. Wave 2.
</objective>

<context>
From 01-01: `Machine.press`, `tick`, `frame`.
From 01-02: `GameState` fields `facing`, `map_id`, `pos`.

`TileStep` fields: `direction`, `turned`, `moved`, `map_before`, `map_after`, `warped`, `frames`.

`TileStepper(machine, reader)`:

- `step(direction) -> TileStep`
- Turn only when `state.facing` is not already that direction. Turn is one press of 8 frames.
- Walk is one press of 8 frames, then 12 frames of wait.
- If `map_id` changed, tick 180 more frames and set `warped=True`.
- `moved` is true when `pos` changes or the map changes.

Facing names are the four strings the reader already returns (`up`, `down`, `left`, `right`). Do not read `wPlayerDirection` bits here.
</context>
