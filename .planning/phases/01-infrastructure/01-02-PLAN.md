<objective>
Read the game's memory into one frozen snapshot. Names come from the symbol file. No address is written in this module.

Same boundary as 01-01: no pathfinding, no model, no battle AI. The PDF's combat struct, enemy Pokémon, event-flag blob, and map-object array feed those later systems, so they are not parsed here.

The PDF names `wPlayerStandingMapX` / `wPlayerStandingMapY`. Those symbols are not in our `rom/pokemon_crystal.sym`. Position is `wXCoord` and `wYCoord` (SPEC.md §4.1). Both `wFacingDirection` and `wPlayerDirection` exist. Expose both. Do not trust the PDF's facing bit story until a later measurement; `to_text` uses the SPEC.md §4.1 mapping for `wFacingDirection` only (8 down, 4 up, 2 left, 1 right).

Owner: Wave 1, parallel with 01-01. This file must not import `src.emulator`.
</objective>

<context>
@SPEC.md

`MemoryBus` protocol: `symbol(name) -> (bank, addr)`, `read(bank, addr, n=1) -> bytes`. `Emulator` satisfies it. Tests use a fake bus.

Symbols to resolve, all present in our `.sym`:

- Map and place: `wMapGroup`, `wMapNumber`, `wXCoord`, `wYCoord`, `wFacingDirection`, `wPlayerDirection`.
- Adjacent tiles: `wTileUp`, `wTileDown`, `wTileLeft`, `wTileRight`, `wPlayerTileCollision`.
- Gates: `wBattleMode`, `wScriptRunning`, `wTextboxFlags`, `wMapStatus`.
- Party: `wPartyCount`, `wPartySpecies` (6 bytes), `wPartyMon1HP` / `wPartyMon1MaxHP` through slot 6 (2 bytes each, big-endian).
- Progress: `wJohtoBadges`, `wKantoBadges`, `wNumItems`, `wNumKeyItems`, `wNumBalls`.
- Clock: `wTimeOfDay`.

`COLL_CUT_TREE = 0x12` comes from pret `constants/collision_constants.asm`, not from RAM. Transcribe the `COLL_*` constants. `coll_name` and `is_cut_tree` (0x12 and 0x1A). No walkability table.
</context>
